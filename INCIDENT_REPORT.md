## Инцидент 1. Конфигурация окружения

**СИМПТОМ:**  
- При запуске приложение падало с ошибкой, связанной с отсутствующими или неверно заданными переменными окружения.  

**ПРИЧИНА:**  
- В репозитории не было шаблона переменных окружения (`.env.example`).  
- Разработчики хранили реальные секреты в общедоступных файлах.  
- Это привело к отсутствию стандартизованного набора переменных и ошибкам при старте.

**РЕШЕНИЕ:**  
- Добавлен файл `.env.example` с перечислением необходимых переменных и комментариями по формату (например, `DATABASE_URL`, `SECRET_KEY`, `API_BASE_URL`).  
- Удалены реальные секреты из репозитория.  
- Добавлен `.env` в `.gitignore`.  
- В инструкцию разработчика добавлена команда: скопировать `.env.example` в `.env` и заполнить значения.  
- Пример команд:  
  ```bash
  cp .env.example .env && nano .env
  ```

**КОММИТ:**  
- `fix(env)`: добавлен `.env.example`, удалены секреты, `.env` добавлен в `.gitignore`  
  - Коммит: `[90d60975abfcf18161f3be110ff37d0153927ac6]`

## Инцидент 2. Зависимости

**СИМПТОМ:**  
- При запуске возникали ошибки импорта/инициализации и несовместимости версий.  

**ПРИЧИНА:**  
- В файлах зависимостей (`requirements.txt` / `pyproject.toml`) были зафиксированы жёсткие версии пакетов (хардкод).  
- Эти версии конфликтовали с другими пакетами и с текущим окружением.  
- Также отсутствовала новая необходимая зависимость `pydantic_settings`.

**РЕШЕНИЕ:**  
- Добавлена зависимость `pydantic_settings` в файл зависимостей.  
- Убраны хардкодные версии.
- Выполнены установки в чистом виртуальном окружении и проверена работоспособность:  
  ```bash
  pip install -r requirements.txt
  ```

**КОММИТ:**  
- `fix(deps)`: добавлена `pydantic_settings`, убраны хардкодные версии зависимостей  
  - Коммит: `[90d60975abfcf18161f3be110ff37d0153927ac6]`

## Инцидент 3. Логирование

**СИМПТОМ:**  
- Логи приложения не создавались в ожидаемом месте.  
- При ошибках подключения к БД лог не добавлялся.

**ПРИЧИНА:**  
- В конфигурации логгера указан неправильный путь к файлу логов.  
- Каталог для логов не создавался автоматически.  
- Файл логов отсутствовал в `.gitignore`.  
- Логирование ключевых операций (создание/проверка БД, ошибки подключения) не было реализовано.

**РЕШЕНИЕ:**  
- Исправлен путь к файлу логов в конфигурации (`./`).  
- Добавлена проверка / создание каталога `logs` при запуске.  
- Добавлен `app.log` в `.gitignore`.  
- Добавлено логирование:  
  - `info` при создании и проверке БД;  
  - `error` с `traceback` при неудачном подключении к БД;   

**КОММИТ:**  
- `fix(logs)`: исправлён путь к логам, каталог/файл логов игнорируется, добавлено логирование операций с БД и ошибок подключения  
  - Коммит: `[556836404dde1783bcceafb59f5608c6ba271a28]` и `[cad925d1a2e1f822d2097ba5c6eadbea08018a0c]`

## Инцидент 4. Интеграция фронтенд-бэкенд

**СИМПТОМ:**  
- Фронтенд не мог корректно отправлять запросы к бэкенду.  
- В браузере — ошибки запросов.  
- Запросы шли на неправильный endpoint: `VITE_API_URL=http://localhost:8001/api -> VITE_API_URL=http://localhost:8000/api]`.

**ПРИЧИНА:**  
- В файле `frontend/.env` был указан неверный URL/endpoint для API (опечатка).  
- Поэтому фронтенд отправлял запросы не по адресу бэкенда.

**РЕШЕНИЕ:**  
- Отредактирован `frontend/.env`: исправлен `API_BASE_URL` 
  - `API_BASE_URL=http://localhost:8000`   
- Убедились, что бэкенд принимает запросы на указанном хосте/порту.  
- Протестировано: запросы из браузера и через `postman` проходят успешно, ошибки исчезли.  

**КОММИТ:**  
- `fix(api)`: исправлен endpoint в `frontend/.env` для корректной отправки запросов  
  - Коммит: `[90d60975abfcf18161f3be110ff37d0153927ac6]`
